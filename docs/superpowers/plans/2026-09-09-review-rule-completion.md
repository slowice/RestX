# 检视规则补全实施记录

目标：将已审阅的综合规则转为 code-review 内置规则，并增加用户指定的“自定义规则补全”。

范围：蓝区 code-review/main 规则正文与请求组装、renderer 规则说明、针对规则选择和实际请求的回归测试。不引入跨特性依赖，不改变 IPC、结果字段、存储格式或外部评论行为。

用户补充优先：重点检查低级代码错误；Java 捕获实际具体异常而非直接 catch Exception；所有语言的日志和 console 仅打印脱敏描述，不打印异常堆栈。旧日志“必要堆栈”要求必须移除。

## 能力边界

本次补全模型规则，未新增仓库全文检索、需求文件加载、删除行定位或独立待确认结果 UI。已有 summary 承载上下文限制与待确认说明，结果结构兼容。AI 语义执行效果需要后续使用真实或合成案例评估；本次测试只证明规则选择、分批传递及既有流程正常，不宣称模型能检出所有问题。MR 列表现有历史状态不做规则版本迁移；重新执行检视使用新的缓存指纹。

独立静态评审：检查全部 diff、规则正文、注册、批次传递及缓存版本，未发现可操作问题。

主干整合复测发现 CRLF frontmatter 末尾布尔值解析错误。新增失败回归后，在解析前统一 CRLF 为 LF；最终相关测试增加到 17 项。
