# RestX 知识图谱编辑功能设计

## 目标

在现有只读知识图谱上增加显式编辑模式。用户可以连续修改多个问题的分类关联、创建被问题引用的新标签，以及全局语义删除场景、能力和知识标签，最后一次性保存到对应 Markdown Frontmatter。Markdown 文件仍是唯一事实来源，不引入数据库或独立图谱文件。

## 已确认范围

- 页头提供“编辑”入口，编辑态提供“取消”和“保存”。
- 一次编辑会话允许修改多个问题和标签，所有变化先保存在 renderer 内存草稿中。
- 问题节点可以修改一个场景、多个能力和多个知识标签。
- 待整理问题也可以在编辑态被选中并补充完整分类。
- 新标签必须在创建时关联到一个问题，不允许保存孤立标签节点。
- 删除问题节点是语义删除：清除该问题的受控分类字段，使其回到待整理区，不删除 Markdown 文件或正文。
- 场景、能力和知识标签节点都支持全局语义删除：从所有引用问题中移除该标签。
- 某个标签不再被任何问题引用时，它自然从聚合图谱中消失。
- 只有用户点击“保存”才会写盘；取消会丢弃本次全部草稿修改。

不包含标签重命名、Markdown 正文编辑、文件删除、撤销历史、孤立标签管理或新的持久化介质。

## 数据模型与草稿

现有 `scene`、`capability`、`knowledge` Frontmatter 继续作为关系来源。场景、能力和知识节点仍由问题标签聚合而成，不升级为独立实体。

进入编辑模式时，renderer 根据当前扫描结果建立草稿。草稿按问题 ID 保存：

- 当前分类值，或者表示未分类的空值；
- 进入编辑模式时的 `sourceFingerprint`；
- 是否相对初始值发生变化。

图谱和标签词表从草稿即时派生。修改一个问题后，页面立即显示保存后的预期结构；尚未满足一个场景、至少一个能力和至少一个知识的问题出现在待整理区。新标签只有在至少一个草稿问题引用时才会进入图谱。

标签全局删除通过遍历草稿中所有问题的分类完成。删除场景标签会清空匹配问题的场景；删除能力或知识标签会从相应数组移除匹配项。由此失去完整分类的问题进入待整理区，但保留剩余的有效标签草稿，以便用户继续补充。

标签比较和去重沿用现有规则：去除首尾空白、忽略大小写匹配，并复用已有规范显示名称。一个问题只能有一个场景，可以有多个能力和知识。

## 交互设计

### 页面状态

查看态保持现有行为。页头新增“编辑”按钮；进入编辑态后，“打开目录”和普通刷新不再直接执行，页头主要操作变为“取消”和“保存”。

编辑态下：

- 选择已整理或待整理问题时，右侧检查器切换为分类编辑器。
- 场景使用单选控件；能力和知识使用可增删的多选标签控件。
- 每类控件都可以从当前标签词表复用标签，也可以输入符合校验规则的新标签。
- 清空问题分类提供明确的“移回待整理”操作，不使用文件删除措辞。
- 选择场景、能力或知识节点时，右侧显示标签类型、名称、引用问题数量和“删除标签”操作。
- 删除标签前二次确认，并展示受影响问题数量；确认只更新草稿。
- 图谱节点和连线随草稿更新。全局删除导致当前所选节点消失时，清空选择并给出轻量状态提示。

草稿未改变时“保存”禁用。保存期间锁定编辑操作并显示进行中状态。存在未保存修改时，取消编辑、刷新或离开知识图谱路由需要确认；确认放弃后恢复最近一次扫描结果。

### 保存反馈

保存成功后退出编辑态，使用 main 返回的重新扫描结果刷新页面，并给出成功提示。保存失败时保留草稿和编辑态：

- 外部文件变化：提示哪些问题发生冲突，要求用户放弃草稿并刷新后重新编辑；不自动覆盖。
- 输入校验失败：定位到相应问题或标签字段。
- 写入失败但回滚成功：提示没有保留本次更改，可以重试或取消。
- 回滚不完整：明确提示受影响文件已备份，建议打开知识目录人工处理；不得宣称整批保存成功。

## IPC 与 main 边界

新增知识图谱批量编辑契约。renderer 只提交发生变化的问题，单项包含：

- 当前快照中的问题 ID；
- 进入编辑模式时的内容指纹；
- 完整的新分类，或清除受控分类的语义操作。

renderer 不提交绝对路径、原始 Markdown 或任意 IPC channel。main 使用当前扫描快照解析问题 ID，并执行以下流程：

1. 校验请求数量上限、问题 ID 唯一性、标签类型、长度、数量和规范化结果。
2. 重新安全读取全部目标文件并比较内容指纹。
3. 只要任一文件无效、丢失或指纹冲突，整批拒绝，且尚未创建替换结果。
4. 在内存中生成每个文件的新 Frontmatter；保留正文、未知元数据和可保留的 YAML 结构。
5. 为全部目标文件创建带时间戳的私有备份和同目录临时文件。
6. 逐个原子替换目标文件。
7. 若替换中途失败，利用本批次备份恢复已经替换的文件，并清理临时文件。
8. 全部成功后重新扫描并把权威结果返回 renderer。

文件系统不提供跨多个 Markdown 的真正原子事务，因此该流程是“全量预检 + 单文件原子替换 + 失败补偿回滚”，不能把它描述成数据库级事务。备份即使保存成功也保留，继续沿用 `.restx-backup` 安全边界。

清除问题分类时只删除 RestX 管理的 `type`、`scene`、`capability`、`knowledge` 字段，保留其他 Frontmatter 字段和正文。若清除后 Frontmatter 没有其他字段，则移除空 Frontmatter 块；该序列化结果由测试固定，避免留下无意义结构。

## 组件边界

- `KnowledgeMapPage`：拥有查看态／编辑态切换、草稿生命周期、保存和离开确认，不直接实现文件写入。
- 图谱草稿领域模块：负责从问题分类派生图谱、应用单问题修改、全局标签删除、差异计算和规范化；保持为无副作用函数，便于精简测试。
- `LayeredKnowledgeGraph`：在编辑态暴露标签节点选择，并继续把问题节点选择交给页面；不持有业务草稿。
- 问题分类编辑器：只编辑一个问题的草稿分类，复用标签词表和公共校验规则。
- 标签检查器：展示引用影响并发出全局删除意图，不自行修改其他问题。
- `KnowledgeService` 与批量写入服务：执行 IPC 后的全量预检、备份、替换、补偿回滚和重新扫描。

上述代码全部留在 `src/features/knowledge-map/` 蓝区特性胶囊中，不向 platform 放置知识图谱专用逻辑，也不扩大 preload 的任意文件访问能力。

## 异常与并发

- 编辑期间外部修改 Markdown 不会静默覆盖；保存时由每个文件的原始指纹检测。
- 全局标签删除可能影响多个文件，确认框只展示数量和必要的问题标题，不展示绝对路径或正文。
- 无效 YAML 问题保持只读错误状态，不能通过批量编辑覆盖；用户需先在外部编辑器修复。
- 批量请求设置明确的问题数量上限，避免 renderer 构造无界写入。
- 保存按钮防止重复提交；保存完成前不允许开始新的编辑会话。
- 离开确认仅保护 renderer 草稿，不创建自动保存或恢复文件。

## 测试与验证

自动化测试保持精简，覆盖以下高价值路径：

- 草稿中修改问题分类后正确重建节点、边和待整理状态。
- 全局删除场景、能力、知识分别影响全部引用问题，且不产生孤立节点。
- 新标签只能随问题关联出现，大小写和空白规范化沿用现有行为。
- 批量写入在任一指纹冲突时不修改任何目标文件。
- 成功保存时为每个修改文件建立备份，保留正文和未知 Frontmatter 字段。
- 中途替换失败时恢复已经替换的文件，并准确报告回滚状态。
- 页面进入编辑、修改多个问题、取消、保存和标签删除确认的核心交互。

完成实现后运行仓库要求且与改动相关的最小检查。随后启动独立端口的真实 Electron 应用，使用隔离测试知识目录验证：

隔离目录通过仅在 development 启动时生效的 main 进程环境变量 `RESTX_KNOWLEDGE_ROOT` 指定；生产启动忽略该变量，renderer 仍无法提交任意路径。

1. 编辑多个问题但取消后磁盘不变。
2. 新建并关联标签后保存，重启或刷新后关系仍存在。
3. 全局删除三类标签时，受影响问题按规则更新或回到待整理。
4. 语义删除问题不会删除 Markdown 文件和正文。
5. 外部修改产生冲突时整批不落盘，草稿仍可见。

## 验收标准

1. 用户可以显式进入和退出编辑模式，查看态不会误触写入。
2. 一次编辑会话可修改多个已整理或待整理问题，并统一保存或取消。
3. 用户可以给问题复用或新建场景、能力和知识标签，不产生孤立节点。
4. 用户可以全局语义删除任意三类标签，并在确认前看到影响数量。
5. 删除问题分类不会删除 Markdown 文件或正文。
6. 保存只修改发生变化的问题 Frontmatter，保留正文、未知字段并生成备份。
7. 任一预检冲突会阻止整批写入；中途失败会尝试恢复已替换文件并准确报告结果。
8. 保存后重新扫描得到的图谱与刷新或重启后的磁盘结果一致。
9. 改动留在知识图谱特性边界内，不扩大 renderer 文件权限或泄露绝对路径。
