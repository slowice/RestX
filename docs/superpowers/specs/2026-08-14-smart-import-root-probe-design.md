# 智能导入根目录探针修复设计

## 背景

用户可以把 AI 工具的数据目录本身选作“扫描根目录”，例如为 `codeagentcc` 选择 `~/.cac`。当前目录 inventory 只包含根目录的子项，并将真实根路径隐藏为 `$SCAN_ROOT`。模型因此无法确认根目录本身是有效目录，可能生成空 `probes`，最终被预置安全校验拒绝。

## 设计

- `collectPresetInventory` 始终把扫描根目录表示为 `{ "path": ".", "type": "directory" }`，随后再收集现有子项。
- 智能导入系统提示词明确说明：当扫描根目录本身就是工具数据目录时，`probe` 和 `source` 应使用 `relativePath: "."`。
- 模型遗漏无安全语义的 `patterns[].label` 时，根据已返回的 `kind` 和 `glob` 生成受控展示标签；路径、匹配规则和查看器仍执行原有严格校验。
- 保持真实绝对路径不发送给模型；不增加自动补全或绕过安全校验。
- 不修改 UI、预置格式、路径校验规则和父目录扫描行为。

## 验收标准

- 直接选择工具数据目录时，请求 inventory 包含根目录 `.`。
- 模型生成以 `.` 为探针和来源的预置可以通过现有安全校验并完成试扫描。
- 选择用户目录并使用 `.cac` 等相对路径的现有流程保持不变。
- 回归测试覆盖发送给模型的根目录元数据以及 `.` 预置的生成、校验和试扫描。
- 回归测试覆盖模型遗漏匹配标签时的本地规范化，避免展示字段阻断有效预置。

## 风险与边界

根目录 `.` 只是已授权扫描根目录的声明式表示，不扩大文件访问范围。修复不根据工具名称自动认定目录，也不在模型输出无效时强行补造探针。
