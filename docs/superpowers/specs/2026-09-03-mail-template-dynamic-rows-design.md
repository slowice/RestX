# 邮件模板动态数据行设计

## 目标

让邮件模板接收由外部 Skill 生成的标准 JSON，同时支持普通变量和行数不固定的表格数据。用户只需在模板中设计一行示例数据并绑定数组；最终邮件按数组项数量自动生成数据行，保留原表格样式。

本需求只负责 JSON 到邮件的模板渲染。Excel、数据库、API 或其他业务数据的采集和整理由外部 Skill 完成。

## 用户流程

### 编辑模板

1. 用户创建或导入邮件模板，并从 Excel 粘贴完整表格。
2. 表格包含固定表头、可选固定表尾和一行示例数据。
3. 用户把光标放入示例行，点击“设为数据行”。
4. 用户填写数组路径，例如 `items`；RestX 自动建议行别名 `item`，用户可以修改。
5. 用户在该行单元格中使用 `{{item.name}}`、`{{item.quantity}}` 等变量。
6. 编辑器以淡色轮廓和“动态行 · items”标签标识该行；该提示不属于邮件内容。
7. 用户保存模板。

工具栏同时提供“取消数据行”，将当前动态行恢复为普通固定行。

### 生成本次邮件

1. 外部 Skill 输出与模板匹配的 JSON。
2. 用户把 JSON 粘贴到“本次数据”。
3. RestX 替换邮件级普通变量，并根据数组内容展开动态行。
4. 用户在预览区确认，然后复制富文本正文或在经典 Outlook 中打开草稿。

## JSON 数据契约

示例：

```json
{
  "reportDate": "2026年9月3日",
  "owner": "张三",
  "items": [
    { "name": "产品 A", "quantity": 10, "amount": 5000 },
    { "name": "产品 B", "quantity": 20, "amount": 7500 }
  ]
}
```

- `{{reportDate}}`、`{{owner}}` 等变量使用邮件级作用域。
- 动态行绑定 `items`，行内使用 `{{item.name}}` 等别名变量。
- 动态行中仍可访问邮件级变量，例如 `{{item.name}}（{{reportDate}}）`。
- 数组路径支持对象路径，例如 `report.items`。
- 数组项中的普通嵌套对象可用点路径读取，例如 `{{item.product.name}}`。
- 第一版不支持嵌套循环。
- 日期按 JSON 中的最终字符串原样显示；日期格式、时区和语言由生成 JSON 的 Skill 负责。

## 模板元数据

动态行绑定保存在模板 HTML 的表格行上：

```html
<tr data-repeat-path="items" data-repeat-alias="item">
```

- `data-repeat-path` 指向 JSON 数组。
- `data-repeat-alias` 定义当前数组项在行内的变量前缀。
- 路径和别名只允许安全的变量路径字符。
- 模板态 HTML 清洗允许这两个受控属性。
- 最终邮件渲染完成后必须移除所有 `data-repeat-*` 属性。
- 编辑器标签和轮廓仅由 renderer CSS 生成，不序列化为邮件样式。

现有存储信封继续使用 v2。绑定元数据位于已有的 `bodyHtml` 字段中，不增加新的顶层持久化字段，因此不需要 v3 数据迁移。旧模板不含绑定属性，继续沿用现有渲染路径。

## 表格约束

- 一张表格最多设置一个动态数据行。
- 一封邮件可以包含多张动态表格，每张表格可绑定不同数组。
- 动态行可以使用横向合并单元格 `colspan`。
- 动态行不得使用跨行合并 `rowspan > 1`；绑定时直接拒绝并提示先拆分。
- 固定表头、固定表尾可继续使用 `rowspan` 和 `colspan`。
- 动态行的边框、背景、字体、宽度、对齐、行高及单元格结构会复制到每个生成行。

## 渲染流程

1. 合并模板默认数据和本次数据，本次数据优先。
2. 替换收件人、抄送、密送和标题中的邮件级变量。
3. 安全解析正文模板 HTML。
4. 对每张含动态行的表格读取 `data-repeat-path` 指向的值。
5. 对数组中的每个对象深克隆示例行，在“数组项别名 + 邮件级数据”的组合作用域中替换文本变量。
6. 用生成的零行或多行替换示例行；数组为空时删除示例行并保留其他固定行。
7. 替换正文其余位置的邮件级变量。
8. 移除全部内部绑定属性和编辑器标记。
9. 执行最终邮件 HTML 安全清洗，并由同一结果生成预览、富文本复制和 Outlook 草稿。

动态行只替换文本节点，不把变量值当作 HTML 解析。所有字符串继续进行 HTML 转义，避免 Skill 输出的数据注入标签或脚本。

## 校验与提示

### 阻止生成或打开 Outlook

- 动态行绑定路径不存在。
- 绑定值不是数组。
- 数组中的任一成员不是对象。
- 某个数组项缺少动态行实际引用的字段，错误定位到例如 `items[2].amount`。
- 动态行包含 `rowspan > 1`。
- 同一张表格包含多个动态行绑定。

### 只提示，不阻止

- 数组为空：删除示例数据行，保留表头和固定行，并提示“items 没有数据”。
- 动态行没有使用对应别名变量：提示用户检查绑定，但允许保存模板。

缺少邮件级普通变量继续使用现有缺失变量规则。错误不得包含完整 JSON 或用户邮件正文。

## JSON 示例生成

页面增加“复制数据示例”操作，根据当前模板生成最小 JSON 骨架：

```json
{
  "reportDate": "",
  "owner": "",
  "items": [
    {
      "name": "",
      "quantity": "",
      "amount": ""
    }
  ]
}
```

- 普通变量生成空字符串占位。
- 点路径生成嵌套对象。
- 每个动态行数组生成一个示例对象。
- 同一变量只生成一次。
- 示例用于交给 Skill 作为输出契约，不自动保存或执行 Skill。

## 代码边界

改动保持在 `src/features/mail-template/` 特性胶囊内：

- `shared/template-engine.ts`：动态行解析、作用域渲染、校验和 JSON 骨架生成。
- `shared/rich-body.ts`：区分模板态与最终邮件态的受控属性清洗。
- `shared/contracts.ts`：扩展可表达动态行提示或错误所需的公开类型，不新增 IPC。
- `renderer/RichMailEditor.tsx`：Tiptap 表格行绑定属性、设置和取消命令。
- `renderer/MailTemplatePage.tsx`：绑定面板、提示和“复制数据示例”。
- `renderer/mail-template.css`：仅用于编辑状态的动态行提示样式。
- `renderer/template-storage.ts`：继续使用 v2，只确保复制和读取模板时保留合法绑定属性。

不修改 `platform`，不增加 main/preload 权限，不改变经典 Outlook 的调用边界。

## 开发与验收

开发阶段不创建或运行自动化测试、类型检查、lint、构建或其他仓库质量门禁。实现完成后使用真实 Electron renderer 做聚焦功能验证：

1. 从 Excel 粘贴带表头和样式的表格。
2. 选中示例行并绑定 `items`。
3. 粘贴含普通变量和三个数组项的 JSON。
4. 确认预览生成三行并继承样式。
5. 确认空数组删除示例行但不阻止打开。
6. 确认非数组、非对象成员、缺失字段和 `rowspan` 得到约定提示。
7. 确认多张表可以绑定不同数组。
8. 确认复制正文和 Outlook 草稿不含 `data-repeat-*` 属性。
9. 确认旧模板的预览和打开行为不变。

当用户明确提出“上库前检视”后，再集中补充有价值的回归测试并执行适用的质量检查。

## 非目标

- 不负责从 Excel、数据库、API 或其他系统采集业务数据。
- 不自动运行或编排 Skill。
- 不提供模板内日期格式化或计算表达式。
- 不支持嵌套循环、条件块、排序、分组或汇总公式。
- 不允许动态行跨行合并。
- 不改变 Outlook 自动发送策略；仍由用户在经典 Outlook 中最终确认。
