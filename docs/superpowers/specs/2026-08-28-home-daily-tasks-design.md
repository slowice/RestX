# 首页登录与每日任务表格设计

## 目标

替换现有首页内容。每次启动 RestX 后，首页先显示登录表单：预填上次保存的账号，密码保持为空。用户输入密码并登录后，本次账号和密码覆盖保存到 `~/.restx/config/`，当前应用会话中的首页切换为可编辑的每日任务表格。

登录是业务入口，不是权限系统。它不锁定侧边栏或其他特性，也不校验账号密码是否正确。登录保存成功后异步执行一个主进程内的预留回调；回调失败只在首页提示，不撤销登录。

任务表格面向个人日常记录，第一版只实现直接编辑、增删行列、自动保存和基础筛选，不引入云同步、多人协作、公式或完整电子表格能力。

## 特性边界

现有 `src/features/home/` 从纯 renderer 特性扩展为完整特性胶囊：

- `renderer/`：登录表单、会话内页面状态、任务表格和样式。
- `shared/`：固定 IPC channel、登录 DTO、表格列/行/快照与公开 API 类型。
- `preload/`：只暴露 home 特性的固定方法，不提供任意 channel 调用。
- `main/`：输入校验、会话状态、凭据存储、任务存储与登录后回调。

home 不再依赖 AI Inspector renderer capability。Shell、路由和其他特性不加入登录专用判断。

## 登录流程

主进程在每次应用进程启动时把 home 会话初始化为未登录。页面加载时调用 `getLoginState()`：

1. 主进程返回上次保存的账号和当前进程内的登录状态，不返回密码。
2. 未登录时，首页显示账号与密码输入框；账号预填，密码始终为空。
3. `login({ account, password })` 校验输入后，通过 Electron `safeStorage` 加密密码并覆盖保存凭据。
4. 保存成功后，主进程将当前 home 会话标记为已登录并立即返回；renderer 显示任务表格。
5. 主进程在后台执行 `HomePostLoginCallback({ account, password })`。默认实现为空函数，后续查询或操作通过替换或注入该实现接入。
6. renderer 在回调运行期间短暂轮询 `getLoginState()`；完成后停止。失败只显示非阻塞提示。
7. 离开首页再返回时沿用当前进程内的登录状态；完全退出并重启 RestX 后重新要求输入密码。

明文密码只存在于登录请求和回调执行期间，不写入日志、不返回 renderer、不长期保存在会话对象中。若 `safeStorage` 不可用或加密失败，登录保存失败并保留表单，不降级为明文保存。

凭据文件使用现有 `electron-store` 模式，位于 `~/.restx/config/home-login.json`，保存版本、账号和加密密码。

## 回调契约

主进程定义窄接口：

```ts
type HomePostLoginCallback = (input: Readonly<{
  account: string
  password: string
}>) => Promise<void>
```

回调由 home 的 main 入口装配，默认 no-op。回调状态只有 `idle | running | succeeded | failed`；对 renderer 只返回状态和简短安全错误，不返回查询结果、密码或异常堆栈。未来若查询结果需要进入页面，应另行设计明确的结果 DTO，而不是扩展为任意 IPC。

## 任务表格

首次使用时创建以下默认列：

| 列 | 类型 | 初始编辑方式 |
| --- | --- | --- |
| 日期 | date | 日期输入 |
| 任务内容 | text | 文本输入 |
| 状态 | select | 待办、进行中、完成 |
| 优先级 | select | 低、中、高 |
| 备注 | text | 文本输入 |

预设列也是普通可编辑列，可以重命名或删除。用户可以新增文本列、删除列、增加任务行、删除行，并直接编辑所有单元格。删除列会同时删除该列的单元格内容，因此界面需要二次确认。

列使用稳定 `columnId`，行使用稳定 `rowId`；单元格按列 ID 保存，所以重命名列不会影响已有数据。自定义列第一版固定为文本类型，避免引入列类型设计器。

默认展示全部任务。页面提供单一关键字搜索，以及日期和状态筛选；这些筛选只影响显示，不修改持久化数据。

数据结构采用带版本的整表快照：

```ts
type HomeTaskTable = {
  version: 1
  columns: HomeTaskColumn[]
  rows: HomeTaskRow[]
}

type HomeTaskColumn = {
  id: string
  label: string
  type: 'text' | 'date' | 'select'
  options?: string[]
}

type HomeTaskRow = {
  id: string
  cells: Record<string, string>
  createdAt: string
  updatedAt: string
}
```

表格保存到 `~/.restx/config/home-tasks.json`。renderer 在编辑后做短暂防抖，然后把完整快照发送给主进程；主进程校验列、行、ID、字段长度和合理数量上限，再通过临时文件加原子替换写入。保存失败时保留 renderer 当前内容并显示可重试状态。

## 公开 API

home preload 只提供以下固定操作：

- `getLoginState()`：读取预填账号、本次会话登录状态和回调状态。
- `login(input)`：覆盖保存凭据并启动登录后回调。
- `getTaskTable()`：读取表格；文件不存在时返回默认模板。
- `saveTaskTable(snapshot)`：校验并原子保存完整快照。

读取任务表不作为安全权限边界；renderer 只在当前首页会话登录后调用它。

## 错误与诊断

错误分为输入无效、安全存储不可用、凭据写入失败、任务读取失败、任务保存失败和回调失败。页面使用简短中文提示；损坏的任务文件不被静默覆盖，主进程返回可恢复错误。

实现阶段为跨进程路径加入固定前缀和固定序号的诊断日志，覆盖登录提交、IPC 校验、凭据保存、回调开始/结束、任务读取和任务保存。日志只记录稳定状态、记录数量和错误类别，不记录账号、密码、任务内容或完整文件数据。

实现阶段同时维护 `docs/diagnostics/home-daily-tasks-runtime.md`，只记录当前端到端调用路径、运行身份、必要日志标记和黄区验证所需的最小证据。

## 开发期验证

本需求仍处于开发阶段，不新增或运行自动化测试、lint、typecheck、构建质量门禁或安全扫描。

实现完成后启动独立端口的真实 Electron 应用，使用隔离的临时用户数据验证以下主流程：

1. 首次启动账号为空、密码为空。
2. 登录后立即看到任务表格，回调默认成功。
3. 增删行、编辑预设单元格、新增/重命名/删除自定义列后数据自动保存。
4. 切换其他菜单再返回，不重复登录。
5. 完全重启应用后账号预填、密码为空，并再次要求登录。
6. 实际检查登录页、全部任务表格和列编辑状态的 Electron renderer 截图。

凭据文件只检查结构、权限和密文存在，不输出或解密密码。开发验证结束后停止临时进程并清理隔离数据。

## 非目标

- 不阻止未登录用户使用 RestX 其他菜单。
- 不把登录作为真实身份认证或授权机制。
- 不提供明文密码查看或自动填充密码。
- 不提供复杂列类型、公式、拖拽列排序、分页、云同步或多人协作。
- 不让回调直接操作 renderer 或使用任意 IPC channel。
