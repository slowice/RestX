# 邮件模板 Excel 表格保真修复设计

## 目标

修复 Excel 表格粘贴到 RestX 时真实边框样式和合并单元格丢失的问题。修复范围止于 Excel 剪贴板进入富文本编辑器及预览的链路，不改变模板数据结构、Outlook 启动流程或表格编辑命令。

## 已确认根因

1. Excel 边框进入 Tiptap 后，浏览器会把颜色转换为 `rgb(...)`，并可能把复合边框拆成多值的 `border-color`、`border-style` 和 `border-width`。现有安全清洗规则不接受这些合法形式，二次清洗时会删除真实边框。
2. 原始 Excel 剪贴板 HTML 超过当前 `500 KB` 限制时，代码会静默退化为制表符纯文本表格。纯文本没有 `colspan`、`rowspan` 或样式信息，因此合并单元格必然被拆开。

## 修复方案

### 边框保真

- 扩展邮件安全样式规则，允许受约束的 `rgb/rgba` 边框颜色。
- 允许 `border-color`、`border-style` 和 `border-width` 使用 CSS 合法的 1 至 4 个值，继续拒绝 URL、表达式、脚本和未知属性。
- 不用 RestX 的默认灰色边框覆盖 Excel 已提供的边框；默认边框只用于源表格没有显式边框的基础表格。

### 合并单元格保真

- 将原始剪贴板 HTML 的硬上限提高到 `4 MB`，用于容纳 Excel 生成的大量 Office 元数据。
- DOM 解析后继续执行现有的最多 500 行、100 列、10,000 单元格限制，并新增规范化结果不得超过邮件富文本正文上限的检查。
- 富文本 HTML 中存在表格但因安全或结构限制无法转换时，不再静默退化为纯文本；阻止本次粘贴并明确提示用户缩小复制范围。
- 只有剪贴板确实没有 HTML 表格、但纯文本包含制表符时，才使用基础表格回退，并提示该模式不包含 Excel 合并和样式。
- `colspan` 和 `rowspan` 保持当前 1 至 100 的边界，经过规范化、Tiptap 编辑和预览后数值必须一致。

## 实现边界

- 修改 `src/features/mail-template/shared/` 的富文本安全样式和限制常量。
- 修改 `src/features/mail-template/renderer/excel-paste.ts` 的结果类型、富文本优先级和失败反馈。
- 修改 `RichMailEditor` 以处理“安全拒绝”结果并显示可执行提示。
- 不引入第三方 Excel 解析器，不读取 `.xlsx` 文件，不扩大 IPC 或系统权限。

## 验收标准

1. 带 `.5pt solid windowtext`、彩色单边和多边颜色的 Excel 单元格，在编辑器 DOM 和预览 HTML 中都保留边框。
2. 同时具有 `colspan="2"`、`rowspan="2"` 的单元格在编辑器与预览中仍保持相同跨度。
3. 原始大小约 `570 KB`、规范化结果在正文限制内的 Excel HTML 走富文本路径，不再退化为六个普通单元格。
4. 超过安全上限或结构限制的 HTML 表格不会修改正文，并显示“缩小复制范围”的错误提示。
5. 只有纯制表符文本时仍可生成基础表格，提示中明确说明不包含 Excel 合并与样式。
6. 现有表格插入、编辑、保存和 Outlook 草稿行为不回归。

## 验证

- 单元测试覆盖浏览器序列化后的 RGB 边框、多值边框和安全拒绝。
- renderer 端到端测试覆盖 `Excel HTML → Tiptap → 预览` 的边框、横向合并和纵向合并。
- 运行邮件模板相关测试和 TypeScript 检查。
- 启动真实 Electron，重复使用已复现问题的约 `570 KB` Excel HTML，检查编辑器和预览 DOM 及可见效果。
