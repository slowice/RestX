## ADDED Requirements

### Requirement: Provider custom request-header configuration
The system SHALL allow every AI Provider, including externally discovered Provider entries, to hold a RestX-managed mapping of custom HTTP request-header names to values. Existing Provider entries without this mapping MUST behave as though it is empty.

#### Scenario: Save headers for a manual Provider
- **WHEN** a user saves valid custom request-header rows for a manual Provider
- **THEN** the Provider state SHALL retain the normalized mapping and return it to the settings page

#### Scenario: Preserve headers for an external Provider refresh
- **WHEN** RestX refreshes a Claude Code Provider that already has custom request headers
- **THEN** the refreshed Provider SHALL retain those headers without modifying the external Claude Code configuration

### Requirement: Custom-header editing and validation
The settings page SHALL provide an editable name/value request-header list for every Provider. Empty rows MUST be ignored, duplicate names MUST use the last row's value, and the system MUST reject empty or invalid header names and values containing carriage-return or line-feed characters.

#### Scenario: Override a duplicate header row
- **WHEN** a user saves two non-empty rows with the same header name
- **THEN** the persisted mapping SHALL contain the value from the last row only

#### Scenario: Reject unsafe header input
- **WHEN** a user saves an empty header name, an invalid HTTP header name, or a value containing a line break
- **THEN** the system SHALL reject the update and leave the existing Provider headers unchanged

### Requirement: Unified custom-header request behavior
The system SHALL apply a Provider's custom headers to its OpenAI-compatible connection test and all normal AI requests. Custom headers MUST override default headers with the same name, including `Authorization` and `Content-Type`.

#### Scenario: Override default authentication
- **WHEN** a Provider defines a custom `Authorization` header
- **THEN** its connection test and normal AI requests SHALL send the custom authorization value instead of the default API-key authorization value

#### Scenario: Add gateway-specific headers
- **WHEN** a Provider defines an additional header not generated by RestX
- **THEN** its connection test and normal AI requests SHALL send that header together with all non-overridden default headers
