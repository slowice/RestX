## Context

RestX 的 renderer 样式按平台和特性胶囊分散维护，目前没有统一的语义字号基线。多个页面直接写入 7px～10px，AI Inspector 的会话标题、路径、时间、搜索结果和 JSONL 详情最为集中。AI Inspector 已有固定的 `revealInFolder(path)` shared/preload/main 链路，并在部分文件行使用，但 Workspace 搜索结果和 JSONL 详情没有入口，详情分栏还会隐藏已有按钮。

## Goals / Non-Goals

**Goals:**

- 用固定语义字号档位提高全应用用户信息的可读性。
- 在不整体缩放页面的前提下适配字号增大后的关键布局。
- 让所有真实历史来源文件入口使用同一个受控定位能力。
- 对未授权和已不存在的文件提供明确、可恢复的错误反馈。

**Non-Goals:**

- 不新增用户可配置字号或 Electron 页面缩放。
- 不改变窗口尺寸、数据格式、历史解析或扫描授权模型。
- 不开放通用 shell、任意路径或历史正文路径访问能力。
- 不为纯 CSS 数值组合增加大量低价值测试。

## Decisions

### 使用平台语义字号变量，而非根字号或整体缩放

在平台 renderer 根作用域定义微型标识、辅助信息、控件/正文和强调正文档位。各特性保留自己的 CSS 所有权，只将用户信息字号映射到平台变量，并在实际拥挤处调整布局。

选择该方案是因为现有样式大量使用绝对 px，单独修改根字号不能完整生效；页面 zoom 又会同时放大间距、图标和容器，容易制造横向溢出。

### 以语义用途决定下限

微型标识最低 10px，辅助信息最低 11px，控件和持续阅读正文最低 12px，主要列表标题使用 13px～14px。路径、日期、错误、表单帮助和按钮文字不能作为装饰性文本降级。

这比机械地给每个字号增加固定数值更能保留原有视觉层级，并避免原本已足够大的标题被不必要放大。

### 复用 AI Inspector 固定定位契约

不新增 IPC channel 或平台级文件 API。renderer 抽取特性内部的定位操作/反馈逻辑，在文件行、会话行、Workspace 搜索结果和 JSONL 详情复用。main 继续先做参数和授权路径校验，再验证目标是仍然存在的文件，最后调用 `shell.showItemInFolder()`。

该决定保持现有安全边界：renderer 无法借此打开扫描范围外的路径，正文中出现的字符串也不会成为可执行文件入口。

### 使用页面内非阻塞错误反馈

定位失败由调用入口捕获并展示简短错误，而不是静默丢弃 Promise 或弹出阻塞系统对话框。错误状态不清除已加载历史，用户可以继续浏览或重试。

## Risks / Trade-offs

- [字号增大导致窄布局拥挤] → 重点检查网格列宽、换行、省略、最小高度和紧凑详情状态，不按比例放大容器。
- [一次迁移涉及多个特性 CSS] → 仅修改字号及其直接引发的布局问题，不顺带重构组件或视觉主题。
- [Electron `showItemInFolder` 不返回定位成功状态] → main 在调用前验证授权和文件存在性；系统调用后的外部文件管理器行为按 Electron 支持能力处理。
- [跨平台视觉和文件管理器差异] → 使用 Electron 跨平台 API；本机完成 macOS 实测，Windows 行为由 API 契约和聚焦测试保障。

## Migration Plan

1. 添加平台字号变量并迁移平台 UI。
2. 按特性迁移承担信息传达的小字号，并处理直接布局回归。
3. 统一 AI Inspector 文件定位入口、存在性检查和错误反馈。
4. 运行聚焦测试和真实 Electron 视觉/功能验收。

回滚可直接撤销 renderer CSS、AI Inspector renderer 和 main 处理器改动；本次没有数据迁移或持久化兼容负担。

## Open Questions

无。字号范围、固定档位、文件定位行为和验收方式均已由用户确认。
