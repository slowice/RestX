# 缺陷管理

入口：左侧「缺陷管理」，路由 `/defects`。特性 ID 为 `defect-manager`。

## 使用

- 新增、编辑、删除问题；问题现象必填，其余字段可逐步补充。
- 问题现象与特征是纯文本；搜索匹配这两列、DTS 编号及分析文件名。
- 每条最多 20 张 PNG/JPEG/WebP 截图，每张输入文件最多 10 MB、4000 万像素。支持文件选择和截图区域粘贴。保存后统一为 PNG，并生成最高 144 × 96 的缩略图；列表显示 48 × 36，点击按需读取原图并放大。
- 分析结果为一个 UTF-8 `.md` 文件，最多 5 MB；点击文件名使用系统默认程序打开。
- DTS 编号按普通文本保存，不限制前缀或数字格式，不自动转为大写，可单独填写或留空；地址留空时显示为普通文本。填写 HTTP(S) 地址后，点击编号在系统浏览器打开。导出 MD 遵循相同规则。
- 编辑中可移除或替换附件；取消编辑不会复制新附件。
- 导出当前筛选结果，无筛选时导出全部。选择目标目录后，新建 `RestX-defects-<随机后缀>/`，包含 `defects.md` 和 `attachments/`。同名原始附件不会互相覆盖。
- 导出表格内截图为可点击的缩略图，分析为文件链接。复制整个导出目录可保留这些相对链接。分析文件正文保持原样，不递归收集其自行引用的其他本地文件。
- IDEA 若单独打开项目外的 MD 时显示破图，先通过 File → Open 打开完整导出文件夹再预览；同时确认 `attachments/` 仍在 MD 旁。桌面反馈样本的 PNG 可正常解码且相对路径正确，暂未复现用户 IDEA 的预览结果，不能据此声称已修复 IDEA。

## 存储与边界

本机 `~/.restx/defects/records.json` 保存版本为 1 的记录，`attachments/` 保存原图、缩略图和 MD 副本，最多 5000 条记录。原始文件移动后不影响已经保存的副本。没有远程上传或 AI 调用。

新附件先落盘，记录通过临时文件原子替换；保存失败清理本次新附件。保存成功后清理被移除的旧附件，删除记录时清理所属附件。文件清理失败记录不包含路径的提示，避免已成功保存的记录被误报为失败。崩溃可能遗留未被引用的附件，保留证据，不自动扫描删除。

renderer 只使用 `window.restx.defects` 固定 API。main 校验字段、标识、文件大小、图片解码、MD 编码与 DTS 协议；已有附件必须属于正在编辑的记录，renderer 不能传入任意读写路径。导出位置由原生目录选择器提供。业务逻辑、样式及数据均位于本特性，平台仅增加注册入口和 API 类型组合。
